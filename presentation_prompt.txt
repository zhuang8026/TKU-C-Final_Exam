### 第 6 頁：Pointer 四大用法

### 第 7 頁：lot_state.bin 持久化設計
問題說明：
- Flask 每次呼叫 subprocess.run() 都是獨立新行程
- C 行程結束後記憶體全部消失，下次呼叫停車場會是空的

解法：
```c
int main(...) {
    LotState *lot = load_state();   // 第一行：讀取上次狀態
    // ... 執行指令 ...
    save_state(lot);                // 倒數第二行：寫回狀態
    free_lot(lot);                  // 最後：釋放記憶體
}
```

序列化順序：Grid → Stack → Queue → History
- Grid：固定大小，直接 fwrite 每一列
- Stack/Queue：linked list 先展開成暫存陣列再寫入
- History：去除 *next 指標，只寫資料欄位（RecordSave struct）

讀取時依同樣順序，逐步重建所有資料結構。

### 第 8 頁：資料結構應用場景與設計理由
說明每個資料結構的選擇理由：

Stack → 單排車道（LIFO）
- 單一出入口，後進先出天然對應
- 被擋住時列出阻擋車牌清單

Queue → 候位系統（FIFO）
- 公平排隊，先來先入場
- 出場後自動觸發 dequeue，下一台自動入場

Linked List → 歷史紀錄
- 筆數無上限，持續只增不刪
- 每次出場 malloc 新節點接在尾端

Dynamic Array → 查詢結果緩衝
- 結果數量事先未知，用 realloc 動態擴充
- 初始容量 4，滿了就 ×2
- 存指標不複製資料，查完只 free 指標陣列

2D Array → 停車格地圖
- 有明確列欄座標，grid[row][col] 直覺對應畫面
- Vehicle 記錄 row/col，出場時精確定位清空格位

### 第 9 頁：資料結構比較表
| 資料結構 | 存取順序 | 新增 | 刪除 | 應用場景 |
|---------|---------|------|------|---------|
| Stack | LIFO | 頂部 O(1) | 頂部 O(1) | 單排車道進出 |
| Queue | FIFO | 尾端 O(1) | 前端 O(1) | 候位排隊 |

| 2D Array | 座標 | — | — | 停車格地圖 |
*容量不足時 realloc 為 O(n)

### 第 10 頁：系統資料流

入場流程：
```
使用者輸入車牌
    → stack 未滿？
```

出場流程：
```

```
